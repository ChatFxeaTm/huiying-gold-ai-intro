01

第一次使用，按这四步来

装到对应平台

MT4 用 EX4，MT5 用 EX5。放进数据文件夹的 MQL4 / Experts 或 MQL5 / Experts。刷新导航器，再拖到交易品种图表上。

先确认管理范围

默认只管“当前品种＋魔术号 886688”的订单。其他品种不在范围内。MT5 需要允许同时持有多空单的对冲账户。

输入手数，检查保护

手数可直接输入，再回车确认；也可快速点 + / -。在参数中分别设置每单保护与整体保护。先用模拟账户熟悉操作。

按需要选择功能

手动交易不必先开网格。启用网格前核对间距、每侧层数和交易时段；关掉网格不会删除已经存在的挂单。

平台的“自动交易 / 算法交易”仍须允许。你点击面板后，订单由 EA 代为提交。因此手动按钮独立于网格，不等于能绕过平台权限、只读账户或正在执行的风控清理。

同一终端的同一品种只加载一个本面板，避免两个执行器同时处理订单。收起面板、移动面板不会停止已开启的交易管理。移除 EA 或关闭终端则会停止客户端管理。

02

鼠标挂单：看到哪里，就选到哪里V1.21 新增

点击“鼠标挂单” → 选择“买挂单 / 卖挂单” → 点击 K 线图上的价格 → 检查预览线、手数和类型 → 点击“确认挂单”。选价后可以拖动虚线调整；按 Esc 或点击“取消”退出。

选择价格位置面板识别为通俗理解
买挂单高于当前 Ask突破买入 / Buy Stop涨到这里，再买。
买挂单低于当前 Ask回调买入 / Buy Limit跌到这里，再买。
卖挂单低于当前 Bid突破卖出 / Sell Stop跌到这里，再卖。
卖挂单高于当前 Bid反弹卖出 / Sell Limit涨到这里，再卖。

距离现价太近时，即使方向选对也不能挂。确认后固定价格和类型；行情变化导致不合法就停止提交，让你重新选价。预览线不是账户订单，也不是已成交仓位。已成功提交的挂单可用“删挂”撤销；此按钮会删除管理范围内的全部挂单。只想撤某一张，请在终端交易列表中操作。

和网格有什么关系？

鼠标挂单是你单独选的一张订单，不占网格层数，不受网格启停和网格时间窗口控制。默认跟随每单 SL / TP 参数，成交后参与每单移损和整体保护。

为什么需要确认？

防止查看 K 线时误点成真实订单。实际面板不会在预览阶段发单；确认前请看清方向、价格、手数。正在清仓、结果未知或账户没有交易权限时仍不能新增订单。

03

挂单最小间距，到底是多少？

没有适用于所有账户的固定数字。券商对每个品种设置最低距离，报价也可能变化。新版面板右下角显示当前单张挂单最小距离，鼠标停留可看到网格首层总间距建议。

先分清三种“距离”

挂单离现价：买挂单相对 Ask，卖挂单相对 Bid。代码使用券商 StopLevel，再加一个最小价格跳动作为缓冲。

首层总间距：第一张买 Stop 和第一张卖 Stop 之间的距离。必须容纳点差，以及两侧各自的合法距离。

同侧层间距：第二层到第一层、第三层到第二层的距离。至少一个价格跳动；每张挂单仍须分别满足离现价的距离。

“点”不是固定的美元数

价格距离 = 点数 × 品种的 Point。比如 Point = 0.01，300 点就是价格相差 3.00；如果 Point = 0.001，300 点只相差 0.300。

这是价格变化，不等于账户盈亏。实际金额还取决于手数、合约规格、费用和账户币种。

StopLevel 为 0，也可能存在券商动态距离限制。最终是否接受，以发送当时的服务器反馈为准。查看平台说明

用你品种的数值算一遍

以下是可修改的演示数值，并非当前账户的实时规格。Point、TickSize、StopLevel 可在品种规格中查看；点差以面板为准。

首层总间距保守建议至少133 点

建议额外留出行情变化余量。这里只计算当前公开规格下的距离，不保证下一刻券商一定接受。

计算方式：单张最小距离 = StopLevel + TickSize ÷ Point。首层总间距建议 = 向上取整〔点差 + 2 × 单张最小距离 + TickSize ÷ Point〕。最后额外一跳用于中间锚点对齐；实际发送仍逐价检查。

显示“本轮结束”，为什么没有挂单？

网格的一轮是“固定一组价格，并尝试布置这些层位”，不是保证账户永远有挂单。已成交的挂单变成持仓，已删除或已平仓的层位也不会在单轮模式自动补回。旧版还会把全部跳过或失败也显示成完成；新版区分“本轮未挂成功”，并报告已挂、跳过、失败、待核对数量。

查看顶部提示或悬停看完整详情。价格越位不会追价补单；权限、点差、保证金和券商限制也会阻止发送。需要重新布一轮时，先确认旧网格订单状态，再关闭并重新开启网格；有旧网格订单时会等待，避免叠加。

04

每个按钮，究竟做什么？

按钮实际动作记住这一点
SELL / BUY以面板手数卖出 / 买入一张市价单。左 SELL、右 BUY；网格关闭和网格休息时段都能手动使用。
平多 / 平空关闭范围内对应方向的市价持仓。不会删除挂单。
删挂撤销范围内所有尚未成交的挂单。不会平掉已成交持仓。
平盈 / 平亏逐单按净利润大于 / 小于 0 判断并平仓。考虑已经归属的佣金和隔夜利息；净利润为 0 的单不处理。
锁仓按净手数补一张反方向单。例如多 0.60、空 0.20，再卖 0.40；点差、利息和佣金仍存在。
反手先平全部范围内市价单，再按原净手数反向开单。平仓没完成就不继续开反向单。净手数为 0 时不操作。
网格开 / 关自动布单；按上下固定层位布 Buy Stop / Sell Stop。关闭只停止新增；已有挂单仍可能成交。手数修改只影响下一轮网格。
清仓两秒内再次点击确认，停网格、删挂，再平范围内持仓。确认也保留防抖间隔。清理未完成会继续处理；完成后网格保持暂停。
标题 - / +收起到标题栏 / 恢复面板。EA 继续管理订单。拖动标题移动面板；图表滚动在拖动时暂时锁定，松开后恢复。
使用说明访问本页，查看操作、参数和错误解释。常规版可复制网址，也可从 F7“关于”打开官网链接；网页直达版可点按钮启动浏览器。
05

止损会不会在急行情中“忘了执行”？

不能承诺“绝对没问题”或“亏损必定不超过设定金额”。需要分清：程序有没有持续处理，和市场能不能按指定价格成交，是两件不同的事。

每单硬止损 / 硬止盈

成功设置后的 SL / TP 存在于券商服务器。即使电脑关闭，通常仍由服务器处理；你应在终端交易列表中确认该单已有 SL / TP。

行情跳空、流动性不足、交易暂停等情况下，实际成交价可能偏离触发价。服务器最小距离过大时，面板会把首次 SL / TP 放到合法距离，可能比输入的点数更远。

默认不因 SL / TP 被拒就偷偷发裸单。“允许 ECN 裸单后补保护”默认关闭；打开它会存在从开仓到补好保护之间的空档。

整体保护与移动保护

整体止盈、止损、保本和移动止盈需要 EA 在线计算总净浮盈。终端关闭、EA 被移除、电脑休眠或网络中断时，客户端不能继续发出清仓请求。

移动止损只有已经被服务器接受的价位，才能在终端离线时继续保护。尚未成功修改的更高保护线，不等于服务器已经收到。

已经确认触发的整体清理任务会保存并继续处理；V1.21 还保存每单应退出的状态及计算出的移损保护线，减少重试时丢失触发的情况。

这次补强了什么？

单单保护一旦明确触发，先记住退出任务，再请求平仓。即使第一次失败后行情反弹，也不会把这次退出忘掉。移动止损计算出的更优保护线会保存：若改单失败、随后行情越过这条线，在线的 EA 会尝试平该单。整体清理失败时按批次重试，直到剩余持仓和挂单清完；发送结果不确定时停止盲目重复开单。

这些机制提高处理的连续性，并不能消除跳空、断线、服务器拒单或滑点。本版编译和模拟故障测试与真实券商快行情验证是不同的证据，不能把前者当成后者的保证。

功能二：四种整体保护，各自开关

保护举例触发后
整体止损设 100：范围内总净浮盈降到 -100 或更低。暂停网格并清理挂单、持仓。
整体固定止盈 新增打开开关，设 100：总净浮盈达到 +100。直接开始清理，不等待回撤。
整体保本先赚到 30，激活保护；回落到 5 时开始清理。“锁定 5”是触发线，不是最终到账保证。
整体移动止盈赚到 50 开始；峰值后来到 80，允许回撤 10，保护线变成 70。峰值继续升，保护线跟着升；回落时保护线不后退。

金额均使用账户币种，美元账户通常为美元，其他币种或美分账户须看账户显示。这里统计的是范围内当前市价持仓的净浮盈，不是当天累计已实现利润，也不保证覆盖未来平仓才收取的费用。保本与移动止盈同时开启，使用两者中更高的保护线；无市价持仓时复位组合峰值。

06

参数字典：用普通话把设置讲清楚

按 F7 打开 EA 属性的“输入参数”。下面保留英文变量名，方便和文件、日志对应。默认值是开发联调用的示例，并不适合所有品种。

基础设置7 项
  • 魔术号：隔离本面板订单

    MagicNumber · 示例默认：886688

    订单的识别编号。默认 886688。只有品种和编号都相符的订单，才由默认管理模式接管。改编号可能使已有订单离开管理范围，持仓时不要随便改。

  • 首次加载默认手数

    DefaultLot · 示例默认：0.10

    没有保存过手数时的初始值。之后优先恢复上次面板手数；修改这个参数不一定覆盖已经保存的面板手数。

  • 加减手数步长（服从品种步长）

    LotStepButton · 示例默认：0.01

    点击 + 或 - 每次增减多少手。仍要服从券商允许的步长；不是网格层间距，也不是价格变化幅度。

  • 0=本品种本Magic，1=本品种全部订单

    ManageMode · 示例默认：本品种 + 本魔术号 (0)

    ScopeMagic / 0：仅当前品种、本魔术号；ScopeSymbol / 1：当前品种的全部订单，包括其他 EA 或手工单。选择后者会扩大平仓、删挂和保护范围，但仍不涉及其他品种。

  • 订单备注前缀（ASCII，最多8字符）

    OrderCommentPrefix · 示例默认：HY

    订单备注开头，默认 HY，可改成 1 至 8 个英文字母或数字。程序会自动加上网格、手动、锁仓或鼠标挂单等标识。

  • 最大点差(points)，0=不限制新开

    MaxSpread · 示例默认：0

    新开仓或新挂单所能接受的最高点差，单位是 points。0 表示不限制。超过时仍保留平仓、删挂和已有仓位保护能力。

  • 允许滑点(points)

    Slippage · 示例默认：10

    市价请求的允许偏差，单位 points。它不是止损距离，也不能保证所有执行模式或跳空中的最终成交价都在此范围。

功能一：双向网格6 项
  • 首次启动网格，之后恢复已保存按钮状态

    UseGrid · 示例默认：关 (false)

    首次没有保存状态时是否开启网格，默认 false（关）。以后优先恢复已保存的网格按钮状态。需要启停时以面板网格按钮为准。

  • 每侧层数，1至50

    GridLevels · 示例默认：5

    每个方向的层数。例如 5 层表示计划上方 5 张 Buy Stop、下方 5 张 Sell Stop，共 10 张；允许 1 至 50 层。不是最大账户总持仓数。

  • 多空首层总间距(points)

    LongShortGap · 示例默认：300

    第一张买挂单与第一张卖挂单之间的总距离，以中间价格向上下分布。300 点是总间距，不是每边各 300 点。需要满足点差和券商两侧距离。

  • 买侧层间距(points)

    BuyGridStep · 示例默认：300

    买方向相邻两层之间的距离，单位 points。第一层的位置由首层总间距决定；这个参数决定第二层以后有多密。

  • 卖侧层间距(points)

    SellGridStep · 示例默认：300

    卖方向相邻两层之间的距离，单位 points，可以和买侧不同。层数与距离过大导致卖挂价格小于等于 0 时，网格会拒绝启动。

  • 0=单轮，1=自动下一轮

    GridCycleMode · 示例默认：单轮 (0)

    CycleSingle / 0：布完这一轮后不自动补层。CycleAuto / 1：一轮至少成功挂出过订单，且管理范围内市价持仓和挂单都归零后，才开始下一轮。整轮未挂成功时不会死循环重建。

功能一：每单保护10 项
  • 独立硬止损

    UseOrderSL · 示例默认：开 (true)

    是否启用每张订单自己的硬止损。true 是开，false 是关。距离来自 OrderSLPoints。已有更优止损不会向亏损方向放宽。

  • 每单止损(points)

    OrderSLPoints · 示例默认：300

    每张单从自身开仓价计算的止损距离，单位 points。券商要求更远时，初始保护价会扩到合法距离；价格已经越过应止损位置时尝试平仓。

  • 独立硬止盈

    UseOrderTP · 示例默认：开 (true)

    是否启用每张订单自己的硬止盈，与整体止盈开关互相独立。关闭此项不代表关闭整体止盈。

  • 每单止盈(points)

    OrderTPPoints · 示例默认：500

    每单止盈的价格距离，单位 points。比如 Point 为 0.01 时，500 点代表价格相差 5.00，不是固定赚 500 美元。

  • 独立移动止损

    UseTrail · 示例默认：开 (true)

    每张市价单的移动止损开关。盈利达到启动距离后，让止损跟随有利价格移动；关闭不会主动删除服务器已存在的止损，也不会撤销已经触发的平仓任务。

  • 盈利启动距离(points)

    TrailStart · 示例默认：150

    单笔价格盈利达到多少 points，才开始移动止损。不是组合利润，也不是账户币种金额。

  • 跟随价格距离(points)

    TrailDistance · 示例默认：80

    移动止损与当前平仓报价之间保持的距离，单位 points。多单看 Bid，空单看 Ask；券商要求更大距离时使用更大的合法距离。

  • 最小SL改善(points)，可为0

    TrailStep · 示例默认：10

    止损至少改善多少 points 才再次修改。设得小更灵敏但可能更频繁；0 也不会反复提交完全相同的价位，仍受改单时间限制。

  • 同一订单最短修改间隔(ms)

    MinModifyIntervalMs · 示例默认：300

    同一张单两次保护修改之间的最短间隔，单位毫秒。默认 300 毫秒。它控制改单频率，不是实际成交或网络响应时间保证。

  • 锁仓单是否使用硬SL，默认不启用TP/Trail

    HedgeUseSL · 示例默认：关 (false)

    锁仓单是否附加硬止损。默认 false。锁仓单默认不启用单单止盈和移动止损，避免保护功能自动拆掉一边；整体保护仍可能处理锁仓单。

功能一：挂单时间5 项
  • 使用服务器时间窗口

    UseGridTime · 示例默认：关 (false)

    是否只在指定服务器时段新增网格挂单。false 为全天。此时段不限制手动买卖、鼠标挂单、平仓或止损管理。

  • 开始时间 HH:MM:SS，含开始秒

    StartTime · 示例默认：09:30:00

    网格允许开始的服务器时间，必须写成 HH:MM:SS，例如 09:30:00，包含开始这一秒。不是电脑时间或北京时间。

  • 结束时间 HH:MM:SS，不含结束秒

    EndTime · 示例默认：16:00:00

    网格停止新增的服务器时间，不包含结束这一秒。支持跨午夜，如 22:30:00 到 02:00:00；启用时开始和结束不能相同。

  • 窗口外清理本面板网格挂单，不平市价单

    DeletePendingAtEnd · 示例默认：开 (true)

    网格窗口外是否清理本面板的网格挂单。不平市价持仓，也不删除鼠标挂单。false 时原网格挂单可能在窗口外继续成交。

  • 下个时段新一轮（需网格ON且无暂停）

    AutoStartNextSession · 示例默认：开 (true)

    进入下一个指定网格时段时，是否准备新一轮。仍需要网格开启且没有暂停或未清理的旧网格；不表示任意时刻都可强制重开。

功能二：整体保护11 项
  • 整体止损独立开关

    UseBasketSL · 示例默认：开 (true)

    整体止损独立开关。打开后看管理范围内全部市价持仓的总净浮盈，达到亏损线就进入统一清理任务。

  • 整体净浮亏达到该金额清仓

    BasketSLMoney · 示例默认：100

    整体允许的净浮亏触发金额。输入正数 100，表示总净浮盈小于等于 -100 时触发；金额使用账户币种。不是最终最大亏损保证。

  • 整体固定止盈独立开关，默认关闭

    UseBasketTP · 示例默认：关 (false)

    新增的整体固定止盈独立开关，默认 false（关）。打开后达到目标金额就清理，不需要等待利润回撤。

  • 净浮盈达到金额后停网格并清仓

    BasketTPMoney · 示例默认：100

    整体固定止盈触发金额，示例 100。总净浮盈达到 +100 就暂停网格并清理全部管理范围订单；不表示一天赚 100 就全天停机。

  • 整体保本独立开关

    UseBasketBE · 示例默认：开 (true)

    整体保本开关。先达到激活利润，再回落到锁定利润时退出；不等于开单立即把止损改到每单成本价。

  • 保本激活金额

    BasketBETrigger · 示例默认：30

    组合净浮盈达到这个金额，才激活整体保本。例如 30 表示先赚到 30。

  • 保本锁定金额，可为0

    BasketBELock · 示例默认：5

    激活保本后保留的利润触发线。例如 5 表示回落到 5 时开始清理；可为 0，须低于激活利润。滑点和未来费用可能使最终到账少于该金额。

  • 整体移动止盈独立开关

    UseBasketTrail · 示例默认：开 (true)

    整体移动止盈开关。跟踪组合净浮盈的最高值，按回撤金额决定退出；不同于每单 Trail 的 points。

  • 整体移动止盈激活金额

    BasketTrailStart · 示例默认：50

    总净浮盈达到这个金额，才激活整体移动止盈。例如 50。

  • 从净浮盈峰值回撤金额

    BasketTrailBack · 示例默认：10

    允许总净浮盈从已记录峰值回撤的金额。例如峰值 80、回撤 10，退出触发线是 70。

  • 0=人工恢复，1=下个时段恢复风控暂停

    RiskResumeMode · 示例默认：人工恢复网格 (0)

    ResumeManual / 0：整体风控清理后，网格保持暂停，需要人为重新开启。ResumeNextSession / 1：启用网格时间窗口时，可在后续时段、账户已清空且状态正常后恢复网格。手动清仓不会按此项自动重开；新版普通手动买卖在清理完成后可独立使用。

界面与执行12 项
  • 面板所处角

    PanelCorner · 示例默认：左上角 (0)

    面板初始停靠的图表角。0 左上、1 左下、2 右下、3 右上。后续可拖动标题栏移动，并记住位置。

  • 横向边距(px)

    PanelX · 示例默认：10

    初始横向边距，像素。和 PanelCorner 配合，后续拖动的位置会保存；修改初始布局参数会重新计算位置。

  • 纵向边距(px)

    PanelY · 示例默认：18

    初始纵向边距，像素。不是 K 线价格或时间位置。

  • 面板缩放，0.8至2.0

    PanelScale · 示例默认：1.0

    面板文字和控件的缩放倍数，默认 1.0，允许 0.8 至 2.0。高分辨率屏幕可适当放大，图表窗口过小时需要留出显示空间。

  • 每批最多交易请求次数，1至3

    RetryCount · 示例默认：3

    一批请求最多尝试几次，允许 1 至 3 次。普通开仓失败后停止该任务；风险清理属于持续清理任务，会同步剩余订单并在后续批次继续处理，直到完成。

  • 有限重试间隔(ms)，100至1000

    RetryDelayMs · 示例默认：250

    同一任务有限重试之间的等待时间，毫秒，允许 100 至 1000。交易仍可能需要更长网络时间；部分异常另有退避等待。

  • 按钮防重复点击(ms)

    ClickDebounceMs · 示例默认：400

    交易按钮防重复点击间隔，默认 400 毫秒。避免一次抖动变成两次开仓。新版手数加减独立使用约 60 毫秒短间隔，不再被这个值拖慢。

  • 新开仓允许的最大报价年龄(秒)

    QuoteMaxAgeSeconds · 示例默认：10

    新增风险动作允许使用的最大报价年龄，默认 10 秒；太久没有新报价就等待。平仓和保护不受这个“新开”年龄限制，但仍要能取得报价和交易权限。

  • 连续严重开仓错误锁止阈值

    SevereErrorLimit · 示例默认：3

    连续出现多少次严重开仓错误后锁住新增订单，默认 3。不能把持续被服务器拒绝的请求当成正常交易反复发送。

  • 允许拒绝SL/TP后先裸单再补保护，默认禁止

    AllowECNFallback · 示例默认：关 (false)

    默认 false。仅在明确知道券商要求先裸单再补保护时使用：第一次带 SL / TP 请求被拒后，后续重试允许不带保护开单，EA 再补。存在裸单空档和补保护失败风险，不能用它来保证止损。

  • 仅核对账户后开启：解除结果未知的开仓锁

    ConfirmUnknownSend · 示例默认：关 (false)

    默认 false。核对持仓、挂单和历史，确认上次未知发送的真实结果后，才临时设为 true 解除未知锁。保持 true 不会每次都重复确认；下一次新的确认需先复位为 false 再明确设 true。不要当作常用开关。

  • 仅核对旧持仓后开启：接受无历史峰值的接管

    ConfirmMissingBasketState · 示例默认：关 (false)

    默认 false。有旧持仓但组合峰值历史丢失时，在核对风险后才临时设 true：接受从当前浮盈重新记录。它不能恢复丢失的最高盈利，也不能还原过去的保护线。

07

遇到提示，先看这里

网格关着，为什么还出现成交？

关闭网格不会撤掉之前已提交的挂单。它们仍留在服务器，达到触发条件时会成交。需要撤掉挂单请用“删挂”；需要一起处理挂单和持仓用“清仓”。

为什么明明按钮可见，买卖仍被拒绝？

买卖不受网格开关和网格时间限制，但必须能连接券商，终端及 EA 允许交易，账户不是只读，品种允许该方向，手数合法，点差没有超过上限。正在风控清理、另一个交易任务没结束、结果未知锁止、旧保护历史缺失时，也不能强行新增风险。顶部显示原因，完整服务器错误码在“专家 / 日志”中。

风险清理结束后，必须开网格才能手动下单吗？

新版不用。清理完成且其他条件允许时，可直接手动买卖或鼠标挂单，网格仍保持暂停。新持仓照常受整体保护；若其净浮盈已达到整体退出条件，会再次触发清理。V1.21 中，清理结束后的锁仓、反手也走手动操作通道；正在清仓、未知成交、费用历史缺失等保护限制仍然保留。

MT4 130、MT5 10016 是什么意思？

通常表示挂单或 SL / TP 的价格距离不符合券商要求，也可能遇到动态距离规则。看品种 StopLevel、当前点差和最小价格跳动，再调整间距。不要把默认 300 点当作所有黄金账户都能接受的固定数。

“待核对”“历史缺失”能直接解除吗？

“待核对”表示一次发送可能已经到达服务器，程序不能确认是否成交，因此不能盲目再发；先查持仓、挂单和历史。“历史缺失”表示有旧持仓却找不到可信的组合峰值，无法知道此前保护线在哪里。相关确认参数只应在你核对后开启一次，不是普通启动必选项。

为什么手数输入后略微变小？

券商可能只允许 0.01、0.10 或其他步长。例如步长 0.01，输入 0.378 会向下规整为 0.37；面板会提示调整。超出最小或最大手数、输入非数字会被拒绝，不能直接发单。请看最终显示的手数。

鼠标挂单到时会自动取消吗？

当前鼠标挂单没有单独的有效期，默认持续有效，直到成交、撤销或券商按规则处理。网格时间窗口只清理网格挂单，不会把鼠标挂单误当成网格删掉。

“网页直达版”为什么要允许 DLL？

纯 MQL 面板按钮不能直接启动外部浏览器。直达版只调用 Windows 自带的 shell32.dll 打开写死的本页地址；不需要另放图片或自行下载 DLL。如果不想开启 DLL，使用根目录的常规版，点击“使用说明”复制网址，或在 F7 的“关于”页面点击官网链接。两版只能选一个加载。

是不是包含了所有想得到的交易功能？

本版完成原规格内的手动操作、突破型双向网格、每单保护、时间控制与组合保护，并新增鼠标四类挂单、直接输入手数和整体固定止盈。没有加入指标信号、自动预测行情、跟单、新闻过滤或全账户跨品种管理。鼠标拖动的是确认前的预览线，不是已提交订单的改单器。
